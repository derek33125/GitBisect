Runtime architecture / model boundary

What the LM-bisect agent actually does

The model is a bounded evidence service inside a deterministic search-and-build loop. This page traces the data boundary and the artifacts produced at every step.

01 / Control flow

LM-bisect runtime architecture

Implemented by command_run_online. Every arrow that changes the search interval originates from a recorded runner verdict, never from an LLM response.

repository and issue state bounded model work build-grounded evidence persisted state

A good verdict removes the older side, a bad verdict removes the newer side, and a skip preserves the interval while recording build-risk evidence. Skip evidence raises bug suspicion only if it itself matches the issue mechanism.

02 / Agent boundary

What enters and leaves the LLM

Extraction and scoring are separate calls. The raw diff is consumed by the extractor; scoring receives the compacted evidence rather than the raw diff.

A
LLM call 1

Diff evidence extraction

Input

Issue context
crash summary, paths, keywords

Candidate context
SHA, subject, changed files
diff mode and base SHA
changed-line diff, up to 600k chars
→

JSON output

{
  "summary": "...",
  "mechanisms": ["..."],
  "touched_symbols": ["..."],
  "risk_relevance": ["..."],
  "build_risk": ["..."],
  "raw_diff_truncated": false
}

Batch extraction is prompt-budgeted. If a batch response fails, the implementation retries its candidates individually before the score phase.

Top-k candidates
message, files, extracted diff evidence
not the raw diff
→

JSON output per SHA

{
  "sha": "...",
  "semantic_score": 0.1..8.0,
  "build_success_prob": 0.05..0.99,
  "evidence": ["..."],
  "features": ["..."]
}

semantic_score estimates relevance; build_success_prob estimates testability. The model does not return good, bad, or skip.

04 / Reproducibility

Per-step artifacts written by the pipeline

The canonical global JSON files are copied into an issue-local artifact bundle so remote result collection does not lose model context or the search path.

observations.json

Runner verdict, trace excerpt, and skip/build-failure evidence for each tested commit.

run-history.json

Selection payload, ranked frontier, model summary, runner timing, and the tested path.

unresolved-window.json

The remaining ordered commit interval after each verdict, used for a safe resume.

model-cache.json

LLM extraction and score output keyed by candidate SHA and diff mode so evidence is not reread.

artifact-bundle-manifest.json

Issue-local manifest that mirrors canonical files under the portable report-trace bundle.
