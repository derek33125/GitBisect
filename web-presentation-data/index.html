LLM-Guided Git Bisect

A build-grounded search pipeline for narrowing a validated LLVM crash interval to its first-bad commit. The model supplies bounded code evidence and ranking; the build runner remains the source of truth.

01 / Search policy

The three methods share the same oracle

Each method starts from the same validated good-to-bad commit interval and calls the same issue-specific build/reproducer script. They differ only in how they select the next commit to build.

Baseline

git bisect

Pure binary search: select the midpoint, build it, classify the reproducer result, and halve the interval.

  • No crash semantics or commit content
  • Build result decides each partition
  • Predictable logarithmic search
Cheap prior

Heuristic-only

Score the full unresolved window using crash-derived keywords, relevant paths, risky terms, and estimated buildability.

  • Scores every unresolved commit
  • No LLM frontier or top-k parameter
  • Calibrated posterior selects a build
Model-guided

Parent diff + LLM extraction

The heuristic creates a bounded frontier. The model extracts semantic diff evidence and contrastively scores only those candidates.

  • Parent diff: parent(candidate) -> candidate
  • Structured extraction, then scoring
  • Runner verdict, not the LLM, updates the interval

Shared build-grounded loop

  1. 1Load unresolved commits
  2. 2Rank candidates
  3. 3Choose one SHA
  4. 4Build and reproduce
  5. 5Persist verdict and narrow

Fewer build steps are better, but a result is counted only when the remaining window is one commit and the runner did not produce a confounding skip.
