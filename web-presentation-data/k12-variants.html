01 / Policy changes

Exactly what changes from the base loop

The base run uses a parent diff, LLM extraction, a semantic top-k frontier, calibrated-posterior selection, and a runner-backed good/bad/skip update. Every card below changes one decision point while retaining the same issue profile, endpoints, runner, and terminal boundary rule.

Base parent-diff + LLM

One deterministic search loop with two model stages

For every unresolved candidate, the deterministic prefilter scores issue terms, paths, and build likelihood. It sends only the top-k candidates to an extraction call, then gives the extracted evidence to the scorer. The selector builds one chosen SHA, records the runner verdict, and contracts the good/bad interval.

# unchanged control flow
records = prefilter(unresolved, issue_profile)
frontier = semantic_top_k(records, k)
diff_evidence = LLM_extract(issue, parent_diff(frontier))
scores = LLM_score(issue, diff_evidence)
candidate = calibrated_posterior_select(scores, unresolved)
verdict = build_and_reproduce(candidate)  # good | bad | skip
unresolved = update_interval(unresolved, candidate, verdict)

Implementation: make_records → resolve_model_frontier → select_next_commit in tools/lm_bisect.py. The four variants below override only the highlighted frontier, extraction, or posterior operation.

Variant 1 / frontier

Evidence-guided diverse frontier

Change: replaces semantic_top_k with a mixed twelve-candidate frontier. It does not change the runner or terminal selector.

# base: frontier = top semantic k
frontier = [semantic_leader,
            posterior_midpoint,
            first_unrepresented_issue_component,
            q25, q75, index_q25, index_q75,
            semantic_fill...]

Why it differs: a single high heuristic score can crowd out a meaningful but lower-ranked component. The component probe forces the LLM to see a relevant subsystem not already represented by the leader.

Trace example, pr204559 step 1: from 19,791 unresolved commits, the frontier included semantic leader 8baf7cc34b00, posterior midpoint 9f500046511e, and a MemorySSA component probe d518f8ff6740 touching llvm/include/llvm/Analysis/MemorySSA.h. The runner selected the midpoint and returned good, reducing the interval to 9,695.

Variant 2 / evidence

Structured causal parent-diff reasoning

Change: BCR replaces the generic raw-diff summary. It keeps the semantic top-k frontier and the shared scorer, but swaps only the extraction stage.

# generic method
parent_diff → LLM_extract(raw diff) → normalized summary → shared scorer

# BCR replacement extraction
parent_diff → file ranking → hunk ranking → context lookup
            → causal LLM extraction → normalized causal evidence
            → shared scorer

What does not happen: no second generic raw-diff summary runs in parallel. The BCR causal extraction is the only extraction output for that candidate. Its normalized causal evidence is supplied as the scorer's diff_summary; generic scorer evidence remains a separate short rationale.

Trace example, pr204559 step 1: candidate d518f8ff6740 extracted ClobberWalker::addSearches, checkClobberSanity, and a loop-carried MemorySSA test. Its causal evidence linked cross-iteration clobber-walker handling to the reported verification assertion with confidence 0.84.

retrieve_causal_diff_evidence; build_causal_diff_extraction_prompt; model_diff_extraction=causal-llm.

Variant 3 / update

Observation-conditioned posterior

Change: replaces the static calibrated prior with a posterior reweighted by the mechanism and component features of prior runner verdicts. The LLM frontier and generic parent-diff extraction stay fixed.

# for candidate c and base prior p0(c)
bad_sim  = max affinity(features(c), bad_observations)
good_sim = max affinity(features(c), good_observations)
w(c) = p0(c) * exp(1.5 * bad_sim - 1.0 * good_sim)
p(c) = w(c) / sum_j w(j)

Why it differs: an observed bad commit raises mass on unresolved commits with similar mechanism/path features; a good observation suppresses them. The interval still contracts exactly from the runner verdict, but the next probe need not follow the original static ranking.

Example: after a bad MemorySSA/ClobberWalker build, unresolved commits sharing term:MemorySSA or the relevant analysis path receive a positive affinity; after a good candidate with the same features, that affinity is subtracted. Generic build: and meta: features are excluded.

observation_conditioned_posterior_probabilities; observation_feature_affinity; defaults bad_strength=1.5, good_strength=1.0, component_weight=0.75.

Variant 4 / frontier policy

Confidence-adaptive frontier

Change: keeps the requested k fixed but chooses between semantic top-k and a diverse frontier using the pre-model semantic margin. It does not use interval size as the switch.

# h1 and h2 are the two best pre-model scores
confidence = max(0, h1 - h2) / max(1, abs(h1))
frontier = semantic_top_k       if confidence >= threshold
           else semantic + posterior_midpoint + index_midpoint

Why it differs: when the heuristic leader is clearly separated, spend the model budget confirming the strongest evidence. When the score distribution is flat, reserve frontier slots for boundary-closing and information-gain probes instead of treating an arbitrary tie as meaningful.

Example: if two plausible commits score 8.0 and 7.8, confidence is 0.025; a threshold above that chooses the mixed frontier. If they score 8.0 and 2.0, confidence is 0.75 and preserves semantic top-k.

semantic_frontier_confidence; resolve_model_frontier; --confidence-adaptive-frontier-threshold.
